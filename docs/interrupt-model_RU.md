## Цель этапа

MyOS уже обрабатывает процессорные исключения на векторах `0x00–0x1F`. Этот этап добавляет управляемый путь для внешних IRQ: сначала legacy PIC 8259A как совместимую стартовую платформу QEMU и большинства BIOS/UEFI-конфигураций, затем PIT channel 0 как источник периодических тиков и PS/2-клавиатуру на IRQ1. На современных ПК APIC/IOAPIC заменяют PIC, поэтому PIC считается именно **переходным учебным контроллером**; после стабилизации ядра появится APIC-слой. [1]

| Компонент | Решение | Обоснование |
|---|---|---|
| Диапазон IRQ | `0x20–0x2F`: IRQ0–IRQ15. | Векторы выше исключений `0x00–0x1F`; стандартный ремап PIC использует master `0x20`, slave `0x28`. [1] |
| PIC 8259A | После ремаппинга все линии маскируются; разрешаются только IRQ0 и IRQ1. | Неожиданные устройства не могут войти в неготовый драйвер. |
| Подтверждение IRQ | EOI выдаётся после обработки: master для IRQ0–7, slave затем master для IRQ8–15. | PIC удерживает IRQ в состоянии обслуживания до EOI. [1] |
| PIT | Channel 0, режим rate generator, 100 Гц. | Channel 0 подключён к IRQ0; 100 Гц достаточно для диагностики и будущего планировщика. [2] |
| Клавиатура | IRQ1, port `0x60`, scan code set 1 в QEMU/legacy-режиме; US QWERTY только для первого этапа. | IRQ1 традиционно связан с клавиатурой; более полный PS/2 driver позднее выделит контроллер и раскладки. [1] [3] |
| Ввод shell | Единый путь получает символы либо из COM1, либо из кольцевого keyboard-буфера; ожидание — `hlt` при включённых IRQ. | Командная строка становится независимой от serial-порта. |

## Порядок инициализации

1. MyOS оставляет GDT и IDT исключений активными, затем добавляет 16 interrupt gates для IRQ.
2. PIC ремаппируется, все IRQ маскируются; PIT и обработчик клавиатуры инициализируются до снятия масок.
3. Разрешаются только IRQ0 и IRQ1. Затем активируется флаг IF инструкцией `sti`.
4. Каждый interrupt stub сохраняет регистры, вызывает `irq_dispatch(irq)`, подтверждает PIC и возвращается `iretq`.
5. Shell вызывает `hlt`, только когда оба источника ввода пусты; внешний IRQ гарантированно разбудит процессор.

> Обработчики IRQ не выполняют форматированный вывод в COM1 и не вызывают shell. Они только увеличивают счётчики либо помещают символ в кольцевой буфер. Это уменьшает время обработки и не смешивает контекст прерывания с интерактивным кодом.

## Тестовая стратегия

Проверка PIT не зависит от человека: shell-команда `ticks` покажет растущее количество обработанных IRQ0. Для клавиатуры QEMU будет запускаться с QMP/HMP-monitor и виртуальной PS/2-клавиатуре будут посылаться события `sendkey`. Этот тест докажет именно аппаратный путь IRQ1, а не serial-ввод. BIOS и UEFI тестируются отдельно с тем же ядром.

## Ограничения этого рубежа

MyOS 0.4.0-dev не будет поддерживать USB HID, раскладки кроме US QWERTY, клавиши с многобайтными scan-code последовательностями, очередь PS/2-команд, SMP, Local APIC или IOAPIC. Эти ограничения не являются ошибками текущего прототипа: они оставлены для следующих совместимых подсистем.
